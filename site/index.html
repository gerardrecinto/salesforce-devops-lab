The release path

Every step is a file in the repo you can read. The first one runs on every push with no Salesforce login.

1

Offline checks

Prettier for Apex, ESLint, Jest for the LWC, PMD through Code Analyzer, and a source to Metadata API conversion. No org needed.

2

Validate the delta

validate-delta.sh sends only the changed files to a sandbox with RunLocalTests. Deleted files stop it.

3

Quick deploy

The job id from step 2 ships that exact payload later with sf project deploy quick, so tests are not run twice.

4

Package versions

release.sh builds account-health-core first, then account-health-ui, which depends on it.

5

Coverage gate

Versions are created with code coverage on. An unlocked package needs 75% to be promoted.

6

Promote

A manual workflow with a protected environment promotes both versions. Nothing promotes on a push.

Run it locally

Needs Git, Node 20 or newer and Java 17 or newer. The first block needs no Salesforce login.

git clone https://github.com/gerardrecinto/salesforce-devops-lab
cd salesforce-devops-lab
npm install --global @salesforce/cli@2.158.7
npm ci
npm run format:check && npm run lint && npm run test:lwc
npm run scan && npm run convert && npm run test:site

Each command exits 0 when it passes. npm run scan prints low severity notes and still passes.

scripts/scratch.sh devhub
sf apex run test --target-org lab --test-level RunLocalTests --code-coverage --wait 10
scripts/validate-delta.sh lab origin/main

This part needs a Dev Hub already authorized as devhub. A free Developer Edition org with Dev Hub turned on works.

What is checked and what is not
  • Checked in CI on every push: LWC Jest tests, ESLint, Prettier, PMD, source conversion, the site logic tests.
  • Not run, because no Dev Hub or sandbox is connected: the Apex tests, scratch org creation, package version creation, validation against a real org, and the two org workflow jobs.
  • This is a lab project. It is not a customer deployment and I do not claim production Salesforce experience from it.
  • The browser Apex check reads text with simple rules. It can miss real problems and can flag fine code. PMD in CI is the real scan.
